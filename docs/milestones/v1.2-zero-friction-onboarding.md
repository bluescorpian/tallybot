# Milestone: v1.2 — Zero-Friction Onboarding

Target: a user can plug in an ESP32-C3 SuperMini running TallyBot firmware, provision
its transport (WiFi credentials or No-TX USB-only mode), and have a working, assigned
tally light — all from inside the TallyBot app.

This milestone delivers the USB serial control channel and provisioning flow described
in [`docs/spec/usb-serial-protocol.md`](../spec/usb-serial-protocol.md).

> **Scope note — in-app flashing is deferred.** The original scope included flashing
> bare ESP32-C3 boards from within the app (no PlatformIO/Arduino IDE required). That
> work is technically designed and unblocked but has been deprioritised in favour of
> shipping the USB provisioning channel and ESP-NOW transport (v1.3) first. Flashing
> will be scheduled into a later milestone once the provisioning pipe is stable.

---

## Implementation order

Work in pieces — each step is testable independently:

1. **USB comms** — firmware COBS framing + HELLO; Rust shell detects device, relays to sidecar
2. **No-TX mode** — WiFi disabled; device only communicates over USB; validates `CompositeDeviceServer`/`UsbTransport`
3. **WiFi provisioning** — `SET_WIFI` + watch `STATUS(wifiState)` stream confirm join before unplug
4. **ESP-NOW** (v1.3) — builds directly on this pipe; only adds a new transport mode and relay

---

## Requirements

- App detects an already-flashed ESP32-C3 when it is plugged in via USB-C (identified
  by `HELLO` frame within ~2 s)
- While plugged in, **all devices communicate over USB** — regardless of their
  provisioned mode; there is no reason to use wireless when a stable wired connection
  exists
- App presents a mode selector for what the device does **when unplugged**:
  - **WiFi** — app provisions SSID + password via `SET_WIFI`; device joins and confirms
    RSSI over `STATUS` while the cable is still attached; operates wirelessly once unplugged
  - **No TX** — WiFi is disabled; the device makes no wireless attempt when unplugged.
    Designed for permanent wired installations where the device is always cabled to the PC
- A WiFi-provisioned device uses USB while plugged in and transitions to WiFi when
  unplugged; a No-TX device uses USB while plugged in and does not communicate when unplugged
- A USB-connected device appears on the board alongside WiFi devices, with an
  indicator that it is wired
- Works on Linux (the dev platform) and Windows (the official release); macOS is out of scope
- WiFiManager SoftAP captive portal is retained as a fallback for field
  re-provisioning of WiFi devices (hold **BOOT** on power-up triggers it when no
  laptop is available)

---

## Acceptance criteria

- Plug in an already-flashed ESP32-C3 → app classifies it as TallyBot firmware within
  ~2 s (HELLO received); no terminal required
- **WiFi path:** select WiFi, enter SSID + password → device joins, streams
  `STATUS(wifiState=connected, rssi=N)` while still plugged in; unplug it → it
  transitions to WiFi
- **No TX path:** select No TX → device immediately appears on the board as a wired
  device, responding to live tally commands via USB; unplug it → it disappears from
  the board and makes no wireless attempt (WiFi is disabled)
- Plug in a device already provisioned for WiFi → it appears on the board with a
  wired indicator and responds to tally commands over USB; unplug it → it transitions
  back to WiFi
- Holding BOOT on a deployed WiFi device still triggers the WiFiManager portal
  (field re-provisioning path unaffected)
