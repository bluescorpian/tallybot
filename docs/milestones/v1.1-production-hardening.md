# Milestone: v1.1 — Production Hardening

Target: reliable device connectivity in real-world venues and better operator visibility
when things go wrong.

The full field-test context — what happened at each venue, ranked causes, and the
remediation detail — is in [`docs/archive/field-test-venue-1.md`](../archive/field-test-venue-1.md).
This doc is the distilled **active worklist**.

---

## Issue 1 — WiFi join reliability

Firmware-side fixes that already landed (bench-verified):
- [x] TX power: full power first, conditional `WIFI_POWER_8_5dBm` fallback (only after
  a failed association, and not on deauth/leave reason codes 3/8)
- [x] Associated-verdict tracking: diagnostics panel now states "joined then dropped" vs
  "never joined"
- [x] Keep-most-diagnostic-reason: our own portal-teardown disconnect can't mask the real
  failure code

Remaining:
- [ ] **WiFi country / channel policy** — set an explicit country (or `WIFI_COUNTRY_POLICY_MANUAL`)
  so channels 12–13 are usable; document channel 1/6/11 recommendation for our own AP
- [ ] **WPA3-SAE** — confirm it's enabled in the build; note PMF behaviour
- [ ] **Connect timeout + retries** — raise `setConnectTimeout` / `setConnectRetries`;
  confirm arduino-esp32 / WiFiManager are on current, known-good versions
- [ ] **Password special-char harden** — verify current WiFiManager URL-decodes
  `# & + % space` correctly; add a parsed-SSID/length echo on the portal

### Issue 1.5 — Bring-your-own AP (recommended deployment)

Document a dedicated 2.4 GHz WPA2-PSK travel router / MiFi as the recommended topology:
simple password, channel 1/6/11, no client isolation, no enterprise/sign-in.  
The "join an existing network" path remains supported once the firmware fixes above land.

## Issue 2 — Operator visibility / diagnostics

Firmware-side fixes that already landed:
- [x] WiFi disconnect reason captured, decoded, classified (auth-fail / not-found / DHCP / timeout)
- [x] Diagnostics panel on the SoftAP captive portal (verdict, last reason + raw code, SSID
  tried, RSSI, stored-password length, FW build stamp, MAC)
- [x] Last-boot diagnostics persisted to NVS — readable after reboot

Remaining (needs sidecar + UI work):
- [ ] **In-app logs panel** fed by the sidecar's existing NDJSON stream
- [ ] **Device→server diagnostic frame** (additive protocol message): connected devices
  report RSSI / IP / uptime / reconnect count / FW version into the app; shown per device
  on the board. Protocol is forward-compatible — extra trailing fields are skippable.

## Acceptance criteria

- Tested on **own AP** (travel router / MiFi): provision → discover → connect → tally;
  all device-local LED states readable at a glance
- Tested on **venue WiFi** with the diagnostics panel: failure reason is legible and
  routes the operator to the right box (network vs PC)
- In-app logs panel shows sidecar events in real time
- Unassigned device shows white breathe, not magenta
